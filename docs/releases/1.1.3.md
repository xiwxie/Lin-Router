# LinRouter 1.1.3 发布说明

日期：2026-09-27。对应 Git Tag 为 `v1.1.3`。

## 修复的问题

旧版在业务 KSP 中生成 `LinRouterAppHub`，并把 `resolver.getAllFiles()` 声明为聚合依赖。即使只修改 MainActivity 方法体，也可能扩大整个 App 的 KSP dirty 集合。开启 KSP 增量编译，并不意味着每个聚合产物的失效范围都足够小。

本次新增 `linRouter.hubMode=isolated`。业务 KSP 继续增量生成模块 RouterLoader、InterceptorLoader、参数 Injector；新的 `generate<Variant>LinRouterHub` 任务从本地 Loader 与当前变体依赖类路径生成 Hub。Hub 不再是业务 KSP 的生成产物，亦不再反向成为它的输入。

## 变更范围

- **router-plugin**：新增可缓存的独立汇总任务。无需业务方提供 anchor 源文件；无需启动第二次 KSP，也无需配置 Room/其他处理器黑名单。
- **依赖发现**：只扫描当前变体编译类路径中 `com.lin.router.generated` 下的 Loader 类，支持 JAR 和类目录，不依赖根项目共享注册集合或其他项目的配置顺序。
- **正确性**：新增、删除和空本地 Loader 都会重新生成 Hub；同名 Loader 冲突直接报错。变体输出目录独立。
- **router-api**：补充固定名 `LinRouterAppHub` 的 R8 consumer keep 规则，覆盖运行时 `Class.forName` 入口。没有修改运行时路由调用链。
- **router-compiler**：处理器算法未改动，继续使用原有合法的聚合依赖。与 v1.1.2 编译器兼容；本次仅统一发布版本配置。
- **发布版本**：三个组件通过 catalog 的 `linRouterRelease` 统一为候选版本，JitPack 版本仍以实际提交/tag 为准。

## 接入与回退

升级插件及 API 后，在根 `gradle.properties` 中显式添加：

```properties
linRouter.hubMode=isolated
linRouter.aggregationMode=auto
```

保持每个路由模块已有的 KSP 插件和 `ksp(router-compiler)` 依赖。官方插件不自动添加 KSP 或 Maven 依赖。`single` 仅适用于确定不需要依赖模块路由的 App，否则会漏掉依赖路由。

如已有业务工程临时独立汇总插件（例如 `AndroidRouteAggregationConventionPlugin`），应先移除或禁用，避免它设置 `linRouter.aggregate=false` 阻止官方插件汇总。也需移除手工 `routerAggregateModules` 参数，避免生成两个 Hub。

回退只需：

```properties
linRouter.hubMode=legacy
```

未配置 `hubMode` 时默认仍为 `legacy`，避免未验证的工程被强制迁移。两种模式可在相同依赖版本下做 A/B 对照。保留既有 `linRouter.aggregate=false` 禁用语义。

### 装载顺序与边界

独立模式默认按依赖 Loader 前缀排序，App Loader 最后装载。旧模式的依赖顺序受项目配置/注册顺序影响；存在跨模块重复路径或同优先级拦截器时，不能假定默认顺序完全一致。可按旧 Hub 的顺序设置：

```properties
# 取旧 Hub 中类名去掉 RouterLoader / InterceptorLoader 后缀的部分
linRouter.loaderOrder=FeatureB,FeatureA
```

未列出的依赖随后按前缀排序，App 仍最后装载。路由 Path、接口及拦截器 priority 值不变。不建议让不同模块依赖同一路径的隐式覆盖行为。

仅发现编译类路径上的模块；不包含仅存在于 runtimeOnly、尚未安装的 Dynamic Feature 或未接入编译依赖的插件模块。`com.lin.router.generated` 是编译器保留包，不应放入手写同名 Loader。

### R8 规则

新 API 的 consumer 规则包含：

```proguard
-keep class com.lin.router.generated.LinRouterAppHub { public <init>(); }
-keep class * implements com.lin.router.api.LinRouterInjector { <init>(); }
-keep interface com.lin.router.api.LinRouterLoader { *; }
-keep class * implements com.lin.router.api.LinRouterLoader { <init>(); }
-keep interface com.lin.router.api.LinInterceptorLoader { *; }
-keep class * implements com.lin.router.api.LinInterceptorLoader { <init>(); }
```

若只升级插件、暂时保留旧 API，请在 App 添加 Hub 的规则。运行时依然会通过固定类名反射创建 Hub，不宣称“零反射”。

## 性能边界

主要优化稳定依赖下的业务代码增量构建。首次/clean 构建增加一次类路径扫描，不保证提速；依赖类路径变动也会使汇总任务失效。业务 KSP、Kotlin 编译和 DEX 仍会正常执行，没有通过跳过必要任务缩短时间。

该优化不增加运行时线程、业务状态、内存缓存或初始化步骤；额外扫描发生在构建机上。JAR 通过 `use` 及时关闭，不把依赖类加载进构建 JVM。未调整 App JVM/GC 参数。

## 验证与兼容范围

独立模式使用 KSP2 的 `KspAATask` 输出接口，不能承诺兼容所有 KSP/AGP。KSP1 请使用 legacy；不支持的任务 API 不会静默退回旧模式。

- 插件编译与任务验证：JDK 17、Gradle 8.11.1、AGP 8.10.0 编译 API、KSP 2.1.21-2.0.2。
- 自动测试：Loader JAR/目录发现、过滤嵌套类、重复类名拒绝、空 Hub、依赖保留、确定性顺序、显式排序；Gradle TestKit 验证 UP-TO-DATE、Configuration Cache、FROM-CACHE、最后一个 Loader 删除。
- 真实 App 结果：见同目录的 `1.1.3-validation.json` 及后续实测记录。
- 未承诺：KSP1 独立汇总、其他 KSP 版本、AGP 7.x 及以下、Gradle Isolated Projects、Dynamic Feature 动态发现。

本地重复检查（不发布）：

```bash
./gradlew :linRouter:router-plugin:test :linRouter:router-plugin:validatePlugins
```

## Git 发布建议

建议提交标题：`perf(router): isolate app hub aggregation from business KSP`

提交范围为本次插件源码、测试、API consumer 规则、catalog/组件发布版本及文档。不要将 IDE 运行状态、本地 SDK 路径、构建产物或临时 App 验证依赖加入提交。

发布前将 `gradle/libs.versions.toml` 的 `linRouterRelease` 改为正式版本 `1.1.3`；提交并由维护者创建 `v1.1.3` tag。JitPack 消费坐标使用实际生成成功的 tag，发布前不要把候选版本当作已经可下载的版本。
